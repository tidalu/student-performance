## Scope and meaning

This audits the user's original pasted build brief, not a newly invented product specification. It covers UI, browser interactions, demo data, local mock behavior needed to demonstrate the UI, accessibility, and requested verification. No real backend, authentication server, ML model, email delivery, or production database is required.

All requested page categories have implementations. That does **not** mean their detailed requirements are complete. The findings below are grouped work items, not a percentage-completion estimate.

- **Missing:** the requested control, content, state, or behavior has no implementation.
- **Partial:** an implementation exists but omits part of the required behavior.
- **Defect:** existing code can behave contrary to the brief.
- **Unverified:** implementation exists, but required demonstration evidence is incomplete; this is not proof the feature is missing.

Evidence: original attachment `Pasted text.txt`; `src/main.tsx`, `src/components.tsx`, `src/features/screens.tsx`, `src/domain.ts`, `src/domain.test.ts`, `src/style.css`, README, FEATURES, DESIGN, UX-CONTRACT and VERIFICATION. This is a source-level requirements audit, with previous browser evidence explicitly distinguished from new checks. No new visual/browser pass or application changes were performed for this report. A static audit cannot guarantee there are no additional runtime defects.

## Recommended implementation sequence

1. **Shared foundations:** A1–A14, B2–B3, D6, I3–I5. Fix routing/context, errors, forms, overlays, state ownership and persistence before adding screen details.
2. **Core journey:** B1, C1–C6, D1–D4. Complete login/upload/preview/dataset/run states and controllable failure demonstrations.
3. **Full-mode screen details:** D5, E1–E3, F1–F5, G1–G6, H1–H4. Reuse shared drawers/export/forms and selectors.
4. **Demo coverage:** I1–I2. Complete the scenario catalogue and truthful armed/consumed feedback.
5. **Acceptance pass:** J1–J7. Verify every page/state/action and refresh screenshots/documentation; then push and redeploy only the completed changes.

## Explicitly excluded from the unfinished list

- A real backend, genuine login security, university data, actual inference/training, email/invitations, paid services and API keys: the prompt excludes these.
- Dark mode, arbitrary column mapping, undo, generated automatic PDF files, cross-tab conflict reconciliation and a production audit-query builder: not required by this brief.
- Optional demo-clock adjustment, local display-name preference, extra quality charts, and a leave-preview confirmation: discretionary wording; their absence alone is not noncompliance.
- Missing exact colors/fonts/pixels of the finance screenshot: the brief requests reference-derived visual language, not a literal copy. Visual completeness still requires the all-page state inspection in J5.
